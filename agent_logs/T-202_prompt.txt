## REQUIREMENTS
### Hyperopt stage
- `hyperopt_args(ctx, class_name, timerange, *, epochs) -> list[str]` — EXACT:
  ["hyperopt", "--config", ctx.ft_config_container, "--strategy", class_name,
  "--strategy-path", ctx.generated_dir_container, "--timerange", timerange,
  "--spaces", "buy", "sell", "roi", "stoploss", "--hyperopt-loss",
  "MultiMetricHyperOptLoss", "-e", str(epochs)].
- `run_hyperopt(ctx, candidate_ids, *, epochs=None) -> dict[int, str]`:
  - epochs = explicit arg or `ctx.miner_cfg.get("hyperopt", {}).get("epochs", 300)`.
  - per candidate: runner.run(hyperopt_args(...train_timerange...), log_dir=<worktree
    agent_logs>, log_name=f"hyperopt_{class_name}.log"). exit_code != 0 -> record run,
    status "failed", add to failed dict, continue.
  - on success: the best-params sidecar `<generated_dir>/<Class>.json` is auto-exported by
    freqtrade (INTERFACES.md header note; D-005). Verify it exists and read it with
    params.read_params_file (invalid -> failed with note). Update the candidate's
    params_path in the store (upsert_candidate with same genome + py_path + new params_path).
    record_stage_run with notes="epochs=<n>". Status "passed".
  - returns {candidate_id: status_string} ("passed"/"failed: reason").
### Validation stage
- `run_validation(ctx, candidate_ids, *, train_metrics=None) -> dict[int, str]`:
  - per candidate: backtest on `validation_timerange` with pipeline.backtest_args (the params
    sidecar is auto-applied by freqtrade when present next to the strategy — no extra flags).
  - parse artifact -> extract_metrics -> record_stage_run(metrics=asdict(metrics)).
  - Gates (ALL must hold, else reject with reason):
    1. fitness.passes_hard_filters(metrics, **ctx.miner_cfg["hard_filters"]) — same bar as train.
    2. If the latest fast_gate metrics for the candidate exist in the store: validation
       max_drawdown_pct <= 1.5 * train max_drawdown_pct (no drawdown explosion).
    3. If train metrics exist: validation profit_factor >= 0.6 * train profit_factor.
    Fetch train metrics from store runs_for(candidate_id, "fast_gate") (metrics dict), fallback
    to `train_metrics` arg mapping {candidate_id: dict} when provided.
  - status "passed"/"rejected: <reason>"; returns mapping.
- `refine_pipeline(ctx, candidate_ids, *, epochs=None) -> dict` convenience: runs hyperopt then
  validation on the hyperopt-passed ids; returns {"hyperopt": {...}, "validation": {...}}.
