## VERIFIED FREQTRADE FACTS (2026.9 — use them, do not re-derive)
- `lookahead-analysis` does NOT signal bias via exit code (always exits 0 on a clean run).
  Machine-readable signal = CSV export via `--lookahead-analysis-exportfilename <path>`
  (only written when total_signals > minimum_trade_amount, default 10). CSV columns:
  `filename,strategy,has_bias,total_signals,biased_entry_signals,biased_exit_signals,biased_indicators`.
  `has_bias` is the hard-reject signal. No CSV row for the strategy -> "bias test inconclusive
  (too few signals)" -> reject.
- `recursive-analysis` has NO csv/exit signal; it prints a table of indicator rows with
  percentage columns (one per startup candle). Parse the percentages from stdout.
- Neither command accepts `--pairs`; both need `--timerange`.

### Walk-forward stage (rolling OOS, params frozen)
- Helper `add_months(ymd: str, n: int) -> str` (stdlib calendar; "YYYYMMDD" in/out).
- `walk_forward_windows(train_start, end, *, train_months=12, test_months=3, step_months=3)
  -> list[tuple[str, str, str]]`: folds (train_start, test_start, test_end) as YYYYMMDD;
  fold k test window = [train_start + train_months + k*step, + test_months]; iterate while
  test_end <= end. Return at least 1 fold when the span allows, else [].
- `run_walk_forward(ctx, candidate_ids, *, train_months=12, test_months=3, step_months=3,
  max_folds=None) -> dict[int, str]`: span = train_timerange start -> validation_timerange end;
  per fold: backtest TEST window only (params fixed; train window is context, not re-optimized —
  document this deviation in a docstring); collect metrics per fold (record_stage_run stage
  "walk_forward" with notes=fold). Gates: median(test profit_factor) >= 1.0 AND fraction of
  folds with expectancy > 0 >= 0.6 -> "passed" else "rejected: <reason>". Fold failures
  (exit!=0 or no artifact) are skipped with note; if >30% folds fail -> "failed".
