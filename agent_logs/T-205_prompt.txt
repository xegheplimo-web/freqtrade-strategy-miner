## REQUIREMENTS
### cli.py
- `main(argv: list[str] | None = None, *, ctx_factory=None) -> int` — testable: ctx_factory
  defaults to `pipeline.make_context`; tests inject a fake. Returns process exit code.
- `build_parser() -> argparse.ArgumentParser` with global `--root PATH` (default: repo root
  derived from `Path(__file__).resolve().parents[2]`) and `--config PATH` (default
  `<root>/config/miner.json`).
- Commands (names FROZEN — INTERFACES.md §6): `generate`, `data-download`, `data-audit`,
  `fast-gate`, `hyperopt`, `validate`, `bias`, `walk-forward`, `robust`, `final`, `report`,
  `status`, `run`. Map to:
  - generate: orchestrator.generate_batch(root, count=--count) -> print manifest path.
  - data-download: runner.run(data.download_args(<cfg container>, cfg pairs, [timeframe],
    timerange)) where timerange = --timerange or derived `train_start-final_end` from cfg
    (train_timerange start .. final_test_timerange end); print exit code + log note.
  - data-audit: data.audit_data(<user_data>/data, pairs, [timeframe]) -> print ok + issues.
  - fast-gate: pipeline.fast_gate.run_fast_gate(ctx, count=--count) -> print result.
  - hyperopt: ids = --ids or store.shortlist(); refine.run_hyperopt(ctx, ids, epochs=--epochs).
  - validate/bias/walk-forward/robust/final: ids = --ids or derived via helper
    `_ids_with_status(ctx, stage, status)` walking store.list_candidates() + stage_status;
    chain stages: hyperopt->"passed"->validate; validation->"passed"->bias; bias->"passed"->
    walk-forward; walk_forward->"passed"->robust; robustness->"passed"->final. final takes
    --force.
  - walk-forward takes --max-folds; hyperopt --epochs; final --force.
  - report: write `output/report.md` (markdown: candidates table with class, strategy_id,
    per-stage status, latest fast_gate metrics if present) + print path.
  - status: print counts by stage/status from the store.
  - run: full sequence data-audit (warn-only) -> fast-gate -> hyperopt -> validate -> bias ->
    walk-forward -> robust -> final; stop when an ids-list is empty; print per-stage summary
    mapping. (This is the E2E acceptance command.)
- All stage outputs: print `json.dumps(..., default=str, ensure_ascii=False)` summaries;
  return 0 on success, 1 on stage failure (any "failed:" statuses) — document choice.
